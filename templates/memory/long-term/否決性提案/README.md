# 否決性提案

> 存放曾被使用者或講師明確否決的方案，防止未來重複討論同一件事。

## 為什麼要有這個分類

不記錄「否決」的記憶會導致：
- 三個月後又提一次同樣的方案，被使用者再糾正一次
- 討論品質下降（一直繞到已否決的方案上）

**紅線**：一個方案被否決 ≥ 1 次就進這裡。

## 格式

一個檔案代表一個被否決方案：

```markdown
---
提案: 一句話說明被否決的方案
否決日期: YYYY-MM-DD
否決理由: 為什麼被否決
重新考慮條件: 什麼情況下可以重新提（若無寫「不重新提」）
關聯: [[相關教訓]]
---

## 完整脈絡
- 誰在什麼情境下提的
- 使用者/講師怎麼回應
- 討論過的替代方案（→ 現行採用的是哪個）

## 若未來 AI 又想提這個方案時
應該看到本檔並直接說「這個已否決，理由是 X」，不要重新提案。
```

## 例子

- `Aqua-fish-vl-threshold調整.md`：討論過 X 方向、被否決、改用 Y

## 使用約定

- **只有明確否決才進**（試過但沒定案不算，那些留在 `教訓/待驗證/`）
- 檔名用中文實務語意（例：「使用A模型跑B任務.md」）
- qmd 會索引這個分類，未來 AI 檢索時能看到「這個方向已被否決」
