## 範例二：錯誤案例

建議路徑：`memory/long-term/教訓/錯誤案例/Windows-Hook中文亂碼.md`

```markdown
---
description: Windows PowerShell Hook 未固定 UTF-8 stdin 時，中文 prompt 會以系統碼頁解讀而寫成亂碼
類型: 教訓
子類: 錯誤案例
狀態: 已驗證
建立日期: 2026-07-18
最後更新: 2026-07-18
來源: 操作紀錄
關聯: [[Windows-Hook固定UTF-8]]
標籤: [Windows, PowerShell, Hook, UTF-8]
---

## 問題摘要
- Hook 有執行，但寫入 state 與 daily 的中文變成亂碼。

## 錯誤訊息或症狀
- `prompt.json` 存在且 JSON 可解析，但 `prompt` 欄位不是原始中文。
- `hook-errors.log` 可能仍是空的，因為這是編碼錯誤，不一定會拋例外。

## 發生情境
- Codex desktop app 以 UTF-8 JSON 傳入 Windows PowerShell 5.1 腳本。
- 腳本直接用 `[Console]::In.ReadToEnd()`，未先指定 UTF-8。

## 根因
- PowerShell 5.1 依目前主控台碼頁解讀 stdin，與呼叫端的 UTF-8 不一致。

## 已驗證解法
- 在讀取 stdin 前，把 `[Console]::InputEncoding`、`[Console]::OutputEncoding` 與 `$OutputEncoding` 設為無 BOM UTF-8。
- 用真正含中文的 JSON 經獨立 `powershell.exe` 程序測試，並讀回檔案比對原文。

## 預防清單
- [ ] Hook 測試必須包含中文，不可只確認 JSON 可解析。
- [ ] 測試要跨程序傳 stdin，不能只在同一程序呼叫函式。
- [ ] 同時檢查 state 與最終 daily。

## 關聯最佳實踐
- [[Windows-Hook固定UTF-8]]

## 來源
- daily/2026-07-18.md — 15:10:00 [任務] 檢查 Hook 與 qmd
```

## 範例三：最佳實踐

建議路徑：`memory/long-term/教訓/最佳實踐/Windows-Hook固定UTF-8.md`

```markdown
---
description: Windows PowerShell Hook 應固定用無 BOM UTF-8 收發 JSON，並以跨程序中文案例驗收
類型: 教訓
子類: 最佳實踐
狀態: 已驗證
建立日期: 2026-07-18
最後更新: 2026-07-18
來源: 操作紀錄
關聯: [[Windows-Hook中文亂碼]]
標籤: [Windows, PowerShell, Hook, UTF-8, 測試]
---

## 摘要
- Hook 的編碼必須由腳本明確設定，不能依賴使用者電腦的預設碼頁。

## 適用情境
- PowerShell Hook 透過 stdin 接收 JSON，或透過 stdout 回傳 JSON／額外 context。

## 標準步驟
1. 在共用入口建立無 BOM 的 `System.Text.UTF8Encoding`。
2. 在第一次讀取 stdin 前設定 Console input/output encoding。
3. 解析 JSON 後保留原始 Unicode 字串。
4. 以外部 `powershell.exe` 程序送入中文 payload。
5. 讀回 state 與 daily，確認中文字逐字保留。

## 驗收條件
- 中文 prompt 在 state 與 daily 中可正常閱讀。
- Hook stdout 是可解析 JSON。
- `hook-errors.log` 沒有新增錯誤。
- 英文、中文與敏感資訊遮罩測試都通過。

## 常見踩坑
- 只設定 `$OutputEncoding`，卻沒有設定 `[Console]::InputEncoding`。
- 測試本身先用錯誤碼頁把中文字轉壞，造成假通過。
- 只測 prompt state，沒有測 Stop 寫出的 daily。

## 關聯錯誤案例
- [[Windows-Hook中文亂碼]]

## 來源
- daily/2026-07-18.md — 15:10:00 [任務] 檢查 Hook 與 qmd
```

## 範例六：錯誤記憶修正

情境全部是虛構資料：

- `人物/自己.md` 原本寫「喜歡喝咖啡」。
- 7 月 20 日使用者明確更正：「我其實不喝咖啡，平常喝無糖茶。」
- 應更新原本的 `人物/自己.md`，不可建立 `自己-新版.md` 或另一份飲料偏好檔案。

更正後的 canonical file：

```markdown
---
description: 學員本人已確認的背景、偏好、興趣、目標與重要關係
類型: 人物
狀態: 已驗證
建立日期: 2026-07-18
最後更新: 2026-07-20
來源: 日記
關聯: []
標籤: [學員本人, 個人偏好]
---

## 摘要
- 學員平常不喝咖啡，偏好無糖茶。

## 飲食偏好
- 飲料：不喝咖啡；偏好無糖茶。

## 變更紀錄
- 2026-07-20：把「喜歡喝咖啡」更正為「不喝咖啡；偏好無糖茶」。
  - 原因：使用者明確指出舊記憶錯誤。
  - 來源：daily/2026-07-20.md — 10:00:00 [對話] 更正飲料偏好

## 來源
- daily/2026-07-18.md — 09:00:00 [對話] 學員人物訪談
- daily/2026-07-20.md — 10:00:00 [對話] 更正飲料偏好
```

整理結果應同時符合：

- `摘要` 與 `飲食偏好` 只把新說法當成有效事實。
- 舊說法只留在 `變更紀錄` 和 append-only daily，供追溯使用。
- `memory/long-term/人物/` 沒有第二份同主題檔案。
- 若原先已有重複檔，合併後移到 `memory/archive/replaced/2026-07-20/人物/`。
- qmd 用新說法查詢會得到目前偏好；用舊說法查詢時不會回答「喜歡咖啡」。

## Organizer ledger 範例

`memory/archive/organizer-ledger.jsonl` 每行只能是一個 JSON 物件：

```json
{"source":"daily/2026-07-18.md","organized_at":"2026-07-18T20:30:00+08:00","targets":["long-term/規則/GitHub推送帳號.md","long-term/教訓/錯誤案例/Windows-Hook中文亂碼.md","long-term/教訓/最佳實踐/Windows-Hook固定UTF-8.md"],"result":"created"}
{"source":"daily/2026-07-20.md","organized_at":"2026-07-20T20:30:00+08:00","targets":["long-term/人物/自己.md"],"result":"corrected","correction_fields":["飲食偏好"],"archived_duplicates":[]}
```

不要把多個物件包成 JSON 陣列，也不要在 `.jsonl` 裡加入註解。
